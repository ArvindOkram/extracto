# Deploying Extracto for $0: Render + Neon + cron-job.org + Discord

```
cron-job.org ──(1) GET /healthz every 10 min in the crawl window ─────► keeps Render awake
             ──(2) POST /runs  Mon/Wed/Fri 06:00 UTC (X-API-Key) ──────► starts a background run
                                                                            │
Render (free web service, Docker) ── crawls the sites in sites.yaml ───────┤
        │                                                                   ▼
        └── Discord webhook ◄── run summary (stats + new/updated pages)   Neon Postgres (free)
```

| Piece | Service | Cost |
|---|---|---|
| App + API | Render free web service | $0 (sleeps after 15 min without requests; ~1 min to wake) |
| Database | Neon free Postgres (or Supabase) | $0 (~0.5 GB storage) |
| Scheduler | cron-job.org | $0 |
| Notifications | Discord webhook | $0 |
| Summaries | Built-in templates (no LLM) | $0 |

Free tiers change; confirm each provider's current limits before relying on them.

---

## 0. Before you start

- [ ] The code is pushed to a GitHub repository (private is fine; Render can read private repos).
- [ ] You know which sites to crawl and have checked their terms of service.
- [ ] You have a contact email for the crawler's User-Agent.

## 1. Where secrets live (never in git)

| Secret | Where it goes |
|---|---|
| `DATABASE_URL` | Render → service → **Environment** |
| `DISCORD_WEBHOOK_URL` | Render → service → **Environment** |
| `EXTRACTO_API_KEY` | Generated by Render (Environment); copy into cron-job.org and Postman |
| `sites.yaml` (site list) | Render → service → Environment → **Secret Files** |
| Local testing values | `.env` on your machine (gitignored) |

`render.yaml` and `.env.example` contain variable **names only**. If a secret is ever committed or
pasted somewhere public, **rotate it** (new webhook, new API key, new DB password); deleting the
commit is not enough.

## 2. Discord webhook

1. Discord → your server → the channel for updates → ⚙️ **Edit Channel**.
2. **Integrations** → **Webhooks** → **New Webhook** → name it "Extracto".
3. **Copy Webhook URL** (looks like `https://discord.com/api/webhooks/<id>/<token>`). Keep it secret.

## 3. Neon database

1. Sign up at neon.tech → **Create project**. Pick the same region as Render: `render.yaml`
   uses `region: singapore`, so choose **AWS Asia Pacific (Singapore)**. The region can't be
   changed later on either service.
2. Open **Connect** (dashboard) and copy the connection string. Prefer the **direct** (non-pooled)
   string; it looks like:
   `postgresql://<user>:<password>@ep-xxxx.<region>.aws.neon.tech/<db>?sslmode=require`
   Extracto converts it for its driver automatically and keeps `sslmode=require`.
3. Nothing else to create: Extracto creates its tables on first use.

Supabase works the same way (Project Settings → Database → connection string), but free projects
pause after about a week without activity.

## 4. Render web service

1. render.com → **New** → **Blueprint** → connect your GitHub repo. Render reads `render.yaml`.
2. When prompted, paste:
   - `DATABASE_URL`: the Neon string from step 3.
   - `DISCORD_WEBHOOK_URL`: the webhook from step 2.
   (`EXTRACTO_API_KEY` is generated for you; `SITES_CONFIG` and `KEEP_RAW_HTML` are preset.)
3. **Apply**. The first Docker build takes a few minutes.
4. Open the service → **Environment** → **Secret Files** → **Add Secret File**:
   - Filename: `sites.yaml`
   - Contents: your site list, for example:
     ```yaml
     defaults:
       user_agent: "Extracto/0.1 (+contact: you@yourcompany.com)"
       delay_seconds: 2.5
       max_pages: 100          # keep realistic: free databases are ~0.5 GB
       max_depth: 3
       timeout_seconds: 20
       max_bytes: 2097152
       exclude_patterns: ['/search(/?$|\?)', "/login", "/cart", "/tag/", '\?page=']

     sites:
       - name: Google Search Docs
         start_url: https://developers.google.com/search/docs/
         allow_patterns: ["^/search/docs"]
     ```
   Save; Render redeploys.
5. Still in **Environment**, reveal and copy `EXTRACTO_API_KEY` (you'll need it below).
6. Note the service URL, e.g. `https://extracto-xxxx.onrender.com`.

The container runs `extracto serve --host 0.0.0.0`, listens on Render's `$PORT`, and refuses to
start if `EXTRACTO_API_KEY` is missing.

## 5. Verify the deployment

Replace `APP` and `KEY` below.

```bash
# 1. Alive (first call may take ~1 minute while it wakes)
curl https://APP.onrender.com/healthz

# 2. Discord works -> a green "Extracto test notification" in the channel
curl -X POST https://APP.onrender.com/notify-test -H "X-API-Key: KEY"

# 3. Start a run (returns immediately with a run_id)
curl -X POST https://APP.onrender.com/runs -H "X-API-Key: KEY" \
     -H "Content-Type: application/json" -d '{}'

# 4. Watch it
curl https://APP.onrender.com/runs/1 -H "X-API-Key: KEY"
```

When the run finishes you get the Discord summary. The first run of each site says
"Baseline saved: N pages (first crawl)"; later runs list new and updated pages.
Interactive docs: `https://APP.onrender.com/docs`.

## 6. cron-job.org schedule

Create a free account at cron-job.org, then two jobs. Times below are **UTC**; set the job time
zone to UTC (or adjust).

**Job 1, "extracto keep-awake"** (Render free sleeps after 15 minutes without requests, even while
crawling, so ping it during the crawl window):
- URL: `https://APP.onrender.com/healthz`
- Method: GET
- Schedule (custom crontab): `*/10 5-9 * * 1,3,5`, every 10 minutes from 05:00 to 09:50 on Mon/Wed/Fri
- No headers needed.

**Job 2, "extracto start run":**
- URL: `https://APP.onrender.com/runs`
- Method: **POST**
- Schedule: `0 6 * * 1,3,5` (06:00 Mon/Wed/Fri; the 05:50 ping has already woken the app)
- Advanced → Headers: `X-API-Key: KEY` and `Content-Type: application/json`
- Request body: `{}`
- Enable failure notifications (email) for this job.

**Size the window:** a run takes about `total pages × 3 s` (polite delay). 10 sites × 100 pages
≈ 50 minutes, well inside 05:00–09:50. For bigger crawls, extend the keep-awake hours.

If a run dies anyway (e.g. Render restarted), it's marked `failed` after 20 minutes without
activity and the next start works normally.

## 7. Day-to-day

- Run history: `GET /runs` (latest 10) and `GET /runs/{id}`.
- Manual run: `POST /runs` with `{}` (all sites) or `{"site": "Name"}`.
- Test a new site without saving anything: `POST /crawl` with `"dry_run": true` (max 50 pages).
- Change the site list: edit the **Secret File** in Render (redeploys automatically).
- Rotate the API key: change `EXTRACTO_API_KEY` in Render, then update cron-job.org.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Render deploy fails at start: "refusing to listen ... without EXTRACTO_API_KEY" | The key env var is missing; add it in Environment |
| `400 config file not found: /etc/secrets/sites.yaml` | Secret File missing or named differently; it must be exactly `sites.yaml` |
| `409 run N is still running` | A run is in progress; check `GET /runs/N` |
| cron-job.org reports a timeout on the 06:00 job | The app was still waking; check `GET /runs`. Make sure Job 1 runs at 05:50 |
| Run marked `failed` with no Discord message | Render slept or restarted mid-run; check that Job 1's window covers the run |
| Database errors mentioning SSL or prepared statements | Use Neon's direct (non-pooled) string with `sslmode=require` |
| No Discord message | `POST /notify-test`; a 502 shows Discord's error (e.g. deleted webhook) |
